# 项目范围与验收

状态：设计基线 v0.1，2026-10-13。面向个人作品展示；尚未在工厂部署。

## 业务范围

用户是设备维修工程师。首期覆盖 ABB ACS580-01 变频器及其电机负载，重点关注过电流、直流回路电压异常、电机缺相、过温与通信异常。以实际核验的资料为准，未覆盖的故障必须说明资料缺失。

输入包括设备型号、可选固件版本、故障现象、告警码及时间、已完成的检查结果。设备实例 ID 不等于型号；文档修订版本不等于设备固件版本。

输出包括诊断状态、排序后的候选根因、逐条引用、建议补充的检查项和明确的证据缺口。仅在证据允许时给出“最受支持的根因”，不将历史相似工单视为对当前设备的直接确认。

不包含实时采集、时序模型训练、预测剩余寿命、设备控制、自动执行维修、企业级权限系统。初始化不包含完整应用开发。

## 输入输出契约（计划）

`POST /diagnoses` 请求：`query`、`model`、`firmware_version`（可空）、`asset_id`（可空）、`as_of`、`observations`、`alarm_codes`。

响应：`diagnosis_id`、`status`（`supported` / `insufficient` / `out_of_scope`）、`root_causes`、`citations`、`next_checks`、`missing_evidence`、`stop_reason`、`usage`。这些字段是设计，不是当前已经可调用的 API。

每个根因包含 `cause_id`、解释和 `evidence_ids`；每条引用包含原始来源、定位器和适用范围。模型输出的概率不直接展示为经过校准的置信度。

## 五类验收场景

| 场景 | 验收行为 |
| --- | --- |
| 明确故障码 | 返回对应型号的解释与排查方向，引用可定位 |
| 跨资料判断 | 结合手册条件与历史工单，解释哪些当前观察支持候选原因 |
| 动态补检 | 指出缺失的证据、记录补检动作，补检结果影响结论或结束原因 |
| 不适用资料 | 保留型号/版本过滤记录，不将其他产品的说明直接套用 |
| 证据不足 | 明确提出待验证假设和具体检查项，不输出确定根因 |

## 初始化完成标准

- 文档间的字段、数据路径、来源和评测口径一致。
- 小批样例包含可回答、证据不足、不在范围内和干扰资料。
- 来源可追溯至官方文件及页码；合成记录明确标识，未经过人类专家复核的内容不写“专家审核”。
- 离线校验能发现断开的证据引用、未来信息泄漏、重复 ID 和错误数据划分。
- 原始 PDF 不进入提交；分支有可复现的 Git 记录。
