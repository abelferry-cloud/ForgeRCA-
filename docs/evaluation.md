# 评测规范

状态：评测设计，未运行 RAG 实验。种子数据只能用于开发和演示准备，不能用于对外宣称真实工业准确率。

## 数据划分与标注

当前提供 `dev.jsonl` 和 `demo.jsonl`；正式 200 条测试集尚未建立。下一阶段扩充 30–50 条开发样本，另建 200 条人工复核、冻结后的测试样本。

建议正式集：可回答 140 条（精确码 40、语义症状 40、跨资料 60），证据不足 40 条，型号/版本不适用 20 条。数量是采样计划，不是现有成果。

标注应包含原始证据位置、可接受根因、排除理由、是否可回答、审核人和争议处理。由一人复核就如实记录，不称“双人专家标注”。问题先基于固定 corpus 设计，再标注；禁止用测试答案生成检索材料。

以维修事件/近重复事件族分组划分。工单的最终根因、处理结果只有在关闭后才可用于其他事件；同一次待诊断事件的闭环记录必须排除，不能仅用截止时间规避身份泄漏。

测试集冻结后不用于调提示词、阈值、chunk 或案例。若修改测试集，变更 dataset_version 并保留原因；公开测试集不能再声称是未见过的私有盲测。

## 三类主对比与消融

| 实验 | 检索 | 图谱 | 动态补检 |
| --- | --- | --- | --- |
| B0 | 向量 top-k | 无 | 无 |
| B1 | BM25＋向量＋RRF＋去重＋Reranker | 无 | 无 |
| B2 | 同 B1 | 有 | 有 |
| A1 | 同 B1 | 有 | 无 |
| A2 | 同 B1 | 无 | 有 |

B0/B1/B2 为简历中的三类方案。A1/A2 用于解释贡献；不能把 B0→B2 的全部收益归因于图谱。

各组共享原始 corpus、切分、embedding、生成模型和答案格式，使用一致的型号/时间过滤与最终上下文预算。精排仅出现在定义了精排的方案。固定生成温度并记录 seed（若供应商支持），不承诺模型完全确定。各组参数完整保存。

## 指标的严格定义

- `Recall@5(q) = |R5(q) ∩ G(q)| / |G(q)|`，在有 gold evidence 的问题上宏平均；`R5` 是最终传给生成器的前五个去重原始证据锚点，不是所有轮次召回的并集。gold 必须尽量标全，存在替代证据时明确等价锚点。
- `Hit@5`：前五条至少命中一条 gold 的问题比例，单独报告，不叫 Recall。
- 多跳完整证据覆盖率：必要证据组是否全部覆盖，避免只命中故障码解释就算完成跨资料诊断。
- `RootCause Top-1`：在 `supported` 样本上，第一根因是否属于 acceptable_cause_ids。空答或拒答算错；别名映射在实验前冻结。
- 证据不足判断：在完整测试集上评估 `insufficient` 的 precision/recall，同时报告 supported 样本被错误拒答的比例。
- 不适用型号正确处理率：在 out_of_scope 子集报告。
- 引用有效率与断言支持率：分别检查“引用存在且适用”和“该引用支持结论”，后者不能只靠字符串匹配。记录人工抽查结果，LLM judge 只能辅助。

评测输出每题记录，不只保留汇总百分比；报告样本数、各类分布和 bootstrap 置信区间。若确实做多次运行，报告重复次数及波动，不虚构重复实验。

## 延迟与成本

在线延迟从服务收到请求到完整答复生成；包含查询改写、检索、图谱查询、验证、生成与重试。报告均值、P50、P95、失败/超时率及冷/热缓存条件。失败请求单独报告，不静默丢弃。

在线 Token 对一次诊断内所有 LLM 调用求和，分别记录 input/output/cached（若可用）；不可获得时用 null，不记 0。重试产生的供应商 usage 也计入。embedding 和 reranker 的资源消耗另记，不能假装成生成 LLM Token。

离线文档抽取与建图单独统计；价格按供应商、模型和计价日期换算。Langfuse 记录 trace_id，每个结果引用对应轨迹。
