# 演示与实施里程碑

## 当前可以展示什么

当前展示的是工程准备：资料来源与文件指纹、合成事件关联、证据定位、评测口径及校验结果。`data/evaluation/demo.jsonl` 是未来现场演示脚本，当前没有聊天页面或诊断 API。

在数据里打开一个 demo 问题，按 gold_evidence_ids 查到知识注释和历史工单，再用定位器打开本地 PDF 页；解释哪些信息属于厂商资料、哪些是虚构历史。这是人工 walkthrough，不是系统已经自动诊断。

未来五个演示场景：

| 场景 | 展示重点 | 不应夸大 |
| --- | --- | --- |
| D001 | 故障码＋当前观察，引用官方说明 | 告警码本身不能唯一确认根因 |
| D002 | 手册＋类似工单，展示证据关联 | 相似历史不是当前设备的直接证明 |
| D003 | 描述缺口、补检历史记录 | 脚本预期不是已经运行的 Agent 轨迹 |
| D004 | 同码异型号干扰过滤 | 尚未验证真实固件版本差异 |
| D005 | 信息不足，提出具体检查项 | 不为了演示强行输出确定根因 |

## M0：初始化（本次范围）

- [x] 业务范围、技术设计、数据规范、评测规范。
- [x] 两份官方 PDF 的来源清单、本地下载与指纹。
- [x] 小批合成工单、告警、开发和演示问题。
- [x] 参考图谱及证据引用检查。
- [x] 离线校验器、异常场景测试与 GitHub Actions。
- [ ] 人类/领域专家复核种子数据（不能由 AI 自称完成）。

M0 完成表示初始化工件可检查，不表示人类复核或应用功能完成。

## M1：基础 RAG

实现 PDF 解析、稳定锚点、索引和向量检索；先用开发样本核对引用，再接入 FastAPI。验收：一条真实手册问题可返回可打开的页码引用，索引没有评测标签。确定实际 embedding 和生成模型、依赖锁文件及本地启动方式。

## M2：混合检索

增加 BM25、RRF、型号过滤、去重和 Reranker。验收：B0/B1 使用相同 corpus 与生成模型，输出逐题结果；错误型号干扰被过滤。使用真实实验决定候选池与 top-k，不预设一定提升。

## M3：图谱增强

实现实体关系抽取、别名消歧、Neo4j 入库和有界查询。验收：每条用于诊断的边能回到来源；参考图仅用于核对；完成 A1 对比并检查错误传播。

## M4：动态补检与追踪

实现 LangGraph 规划/验证/补检、停止条件及 Langfuse 轨迹。验收：充分、无新增、达到上限三种结束路径都能复现；所有 LLM 调用纳入 Token/延迟；完成 A2/B2 对比。

## M5：独立评测与面试展示

冻结正式 200 条样本并人工复核，运行主对比和消融；建立展示界面与启动说明，提供可查看的真实实验报告。失败案例与合成数据局限也进入演示。最终根据实测重新编写简历描述。

每个里程碑独立分支提交。远程初始为空时，首个推送的功能分支可能成为默认分支；后续建立稳定主线时再通过正常评审流程处理，不强推或伪造已有 master 历史。
