# 数据卡模板

> 适用版本：v1（2026-10-19，M0-22）。复制本模板到合适位置后填写，一份数据卡对应**一个可复现的数据版本**，不随日常编辑改写历史条目；内容变化时新建版本并保留旧卡。
> 现有实例：[种子语料数据卡](../data/README.md)、[第三方公开数据卡](public-datasets.md#数据卡)。

## 填写规则

- 只写可核实的事实。未完成的项写「未核验」或「无」，不写推测值。
- 「合成标记」必须能回答：哪些记录是合成的、怎样从字段上识别、不能用于什么结论。
- 「授权」与项目许可证分开写。第三方内容不受 Apache-2.0 覆盖。
- 数据卡本身不是检索语料；它记录的是元数据，不得包含评测答案原文。

## 模板正文

### 1. 标识

| 项 | 内容 |
| --- | --- |
| 数据卡版本 | `<dataset>-v<主>.<次>` |
| 编制日期 | `YYYY-MM-DD` |
| 编制人 / 方式 | 人名或「工具＋AI 生成，待人工复核」 |
| 审核状态 | `unreviewed` / `agent_checked_pending_human` / `human_reviewed` |
| 对应代码版本 | commit 或 tag |
| 是否进入检索索引 | 是 / 否（若为是，须列入 `scripts/corpus_allowlist.py`） |

### 2. 来源

| 项 | 内容 |
| --- | --- |
| 原始来源 / 发布者 | |
| 文档编号、修订或数据集版本 | |
| 获取 URL | |
| 获取时间（UTC） | |
| 文件大小 / 记录数 | |
| SHA-256 | 原始文件与处理后文件分别记录 |
| 官方页面或 DOI | |
| 引用要求 | 论文、DOI 或署名格式 |

### 3. 字段

| 字段 | 类型 | 必填 | 含义 | 备注 |
| --- | --- | --- | --- | --- |
| | | | | |

同时说明：主键是什么、外键指向哪里、时间字段带不带时区、空值如何表示（`null` 与空字符串不可混用）。

### 4. 规模

- 记录数 / 行数、字段数、文件体积。
- 覆盖范围：型号、固件版本、故障码、时间窗。
- 抽样核对数量与结论（例如「抽 30 条，页码与章节均一致」）。

### 5. 合成标记

- 哪些记录是合成的，字段上如何识别（如 `synthetic: true`、`SYN-` 前缀）。
- 合成数据由谁、用什么方法生成，是否经过人工复核。
- **禁止用途**：例如不得写成真实客户历史、不得当作模型效果证据。

### 6. 授权与再分发

- 许可证名称与链接；是否为上游声明而非正式授权文件。
- 原始文件能否提交到 Git（能 / 不能 / 待核实）。
- 署名与改动声明方式。
- 与本仓库 Apache-2.0 的关系（明确写「不覆盖」）。

### 7. 已知偏差

- 采样偏差、场景编排痕迹、类别不均衡、语言/地区偏差。
- 数据规模不足以支撑的结论。
- 已发现但尚未修复的标注问题。

### 8. 标注状态

- 标注人 / 标注方式（人工、规则、模型、混合）。
- 标注一致性检查结果与抽样比例。
- `review_status` 字段取值及其含义。
- 未复核部分的范围。

### 9. 预处理版本

- 处理脚本路径、版本、运行命令。
- 是否可从原始文件完整重建；重建后 SHA-256 是否稳定。
- 中间产物位置（应在被忽略目录，如 `data/processed/`）。

### 10. 使用边界与更新记录

- 允许用于哪些实验、禁止用于哪些实验（跨设备混用、当作根因真值等）。
- 版本变更记录：日期、变更内容、影响范围、是否需要重新标注。

## 完成检查清单

- [ ] 来源 URL、许可页面在填写当天可访问。
- [ ] 原始文件与处理后文件的 SHA-256 均已记录。
- [ ] 合成记录可凭字段识别，且禁止用途已写明。
- [ ] 评测答案、审核意见未被写入数据卡。
- [ ] 若数据进入检索索引，已登记到显式 allowlist 并有隔离测试。
- [ ] 审核状态如实填写，未把 AI 检查写成专家复核。
