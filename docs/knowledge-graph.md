# 知识图谱设计

状态：设计与手工参考样例。`data/graph/reference.json` 用于验证抽取结果，不是已经运行的 Neo4j 数据库。

## 实体与关系

| 实体类型 | 标识方式 | 例子 |
| --- | --- | --- |
| EquipmentModel | 厂商与型号的规范名称 | ABB ACS580-01 |
| FaultCode | 型号命名空间加原始代码 | ACS580-01:2310 |
| Cause | 在项目词表中规范化的原因 | short_acceleration_ramp |

初始化只使用这三种实体，后续有实际需要再增加 Component、Symptom、Check 或 Action。设备实例与型号分别处理。

关系：`HAS_FAULT_CODE`（型号→代码）、`MAY_BE_CAUSED_BY`（代码→候选原因）。每条关系必须保存 `evidence_id`、`basis`（`manufacturer_note` / `synthetic_history`）、`synthetic`。正式抽取再记录 extractor/model/prompt 版本与审核状态。

`MAY_BE_CAUSED_BY` 表示候选解释，不是充分条件或必然因果。一次合成历史事件不能推出适用于所有设备的厂商规则。

## 抽取和消歧

1. 从具备来源锚点的原文抽取实体与关系；保留否定和条件信息。
2. 故障码按“型号＋代码”链接，不能跨品牌只按数字合并。
3. 先用受控别名表匹配型号和常见术语；模糊链接保存候选，有歧义就询问或保持未链接。
4. 只允许当前 schema 中的关系；不因两个实体同段出现就认定因果。
5. 不合并来自不同型号或不同适用版本的冲突陈述。保留各自来源与条件。

## 检索扩展

请求中的型号和故障码是种子；默认最多 2 跳、50 节点、100 边。先过滤型号和诊断时点，再展开关系，使用访问集合防止循环。

将关系映射为其原始证据文本，与 BM25/向量候选一起去重精排。不能直接把图谱中没有出处的路径放入生成上下文。

初始化参考图包含厂商知识注释和合成历史记录支持的边，两者不能混淆。评测系统不读取此参考图作为检索结果，否则会泄漏人工整理的答案。

## 图谱验收

- 抽取节点/边具有有效 evidence_id，定位回原文。
- 代码歧义与型号冲突不会被错误合并。
- 以参考样例评估实体/关系准确性；待人类复核后才能称 gold graph。
- 对比关闭图谱时的检索结果；记录新增有效证据及错误传播，不能只展示一张图声称提升。
